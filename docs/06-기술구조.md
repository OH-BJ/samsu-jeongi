# 06. 기술 구조

## 1. 기술 선택

| 항목 | 선택 | 이유 |
|---|---|---|
| 언어 | JavaScript (ES 모듈) | 설치 없이 브라우저에서 실행, PC와 휴대폰 공통 |
| 렌더링 | Canvas 2D, 480×270 기준 해상도, 최근접 확대 | 도트를 선명하게 유지 |
| 엔진 | 직접 작성한 가벼운 엔진 (프로토타입 코드 확장) | 필요한 기능만 쓰므로 가볍고 빠름 |
| 데이터 | `data/*.js` (JS 객체) | 주석을 달 수 있고, 별도 빌드가 필요 없음 |
| 저장 | localStorage + 저장 코드 내보내기·가져오기 | PC ↔ 휴대폰 이어하기 |
| 테스트·밸런스 | Node.js 시뮬레이터 (`tools/sim/`) | 확률을 수천~수만 번 돌려 검증 |
| 도트 내보내기 | Node (`tools/render-sheet.mjs`) | PNG 시트 생성, 추가 설치 불필요 |

- **실행 방법**: ES 모듈은 파일을 더블클릭(`file://`)하면 동작하지 않는다. 로컬 서버로 연다 (`README.md` 참고).
- **휴대폰에서 하기**: ① 같은 와이파이에서 PC의 로컬 서버에 접속하거나, ② GitHub Pages 같은 무료 호스팅에 올린다(배포 단계에서 함께 진행).

## 3. 핵심 설계 원칙

1. **규칙(systems)과 화면(scenes)을 분리**한다. 전투나 뽑기 규칙은 그림 없이도 돌아가야 시뮬레이터가 같은 코드로 밸런스를 검증할 수 있다.
2. **데이터 중심**. 무기 하나, 적 하나, 대사 한 줄을 추가할 때 `data/`만 고치면 되게 만든다.
3. **뽑기 결과는 즉시 저장**한다. 새로고침으로 결과를 다시 굴리는 꼼수를 막는다(난이도 의도 유지).
4. **시드 난수**: 용도별 난수 스트림을 분리해서, 시뮬레이터에서 같은 상황을 재현할 수 있게 한다.

## 5. 휴대폰 대응

| 항목 | 대응 |
|---|---|
| 화면 방향 | **가로 고정**. 세로로 들면 "기기를 돌려 주세요" 안내를 띄운다 |
| 확대 | PC는 정수배, 휴대폰은 화면에 꽉 차게(비정수 허용, 최근접 보간) |
| 안전 영역 | 노치·홈 바 영역을 피한다 (CSS `env(safe-area-inset-*)`) |
| 터치 | 포인터 이벤트로 통합. 버튼 최소 30×30(기준 해상도) → 실제 화면에서 약 44pt 이상 |
| 조작 | 모든 조작을 탭 한 번으로. 길게 누르면 상세 정보(툴팁) |
| 확대·스크롤 방지 | 두 번 탭 확대, 당겨서 새로고침, 스크롤 막기 |
| 소리 | 첫 탭에서 오디오 잠금 해제 |
| 전체화면 | 설정 메뉴에 전체화면 버튼 |
| 성능 | 스프라이트 캐시, 화면 밖은 그리지 않기, 파티클 수 상한 |
| 이어하기 | 저장 코드(텍스트)를 복사해 다른 기기에 붙여 넣기 |
| (후반) PWA | 홈 화면에 추가, 오프라인 실행 |

## 6. 저장 데이터

- 슬롯 3개 + 자동 저장 1개. 각 저장에 `version` 필드를 두고, 구조가 바뀌면 이전 함수로 옮긴다.
- 저장 항목: 진행(장, 노드, 플래그), 파티와 장비, 인벤토리, 재화, 우물별 천장 카운트, 도감, 설정, 플레이 시간.
